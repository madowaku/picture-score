# Picture Score v0.10-A — Creator Palette Lab Implementation Spec

Issue: #34
Depends on: #18 / PR #27

## Goal
Turn the v0.9 Creator Palette proof into the smallest creator-facing authoring loop:

> Five images + five musical roles -> hear your own world immediately.

The editor should feel like choosing art materials, not programming animation.

## Product boundary

v0.10-A proves only the in-memory authoring loop.

Included:
- one asset slot for each neutral role
- PNG / WebP / SVG import
- role-specific placement preset
- role-specific motion preset
- palette name
- live preview through the existing `ScoreBloomSession`
- Clearing <-> draft palette comparison
- A-E Core Meaning fixture preview
- Reduced Motion
- validation

Deferred to #35:
- persistence
- rename / duplicate / delete
- product-wide palette selector
- IndexedDB asset repository

Deferred later:
- PSD / Live2D / Spine
- automatic image understanding
- cloud sync / marketplace
- public sharing
- timeline editing

## Architectural rule

Do not create a parallel Creator renderer.

The compiled creator draft must become an ordinary `PaletteDefinition` and enter the existing path:

```text
MusicalTimeline
  -> WorldEvent[]
  -> ScoreBloomSession
  -> PaletteRuntime
  -> ScoreBloomLayer
```

No changes to Musical IR or WorldEvent mapping are required.

## Draft model

```ts
export interface CreatorAssetDraft {
  role: PaletteRole;
  fileName: string;
  format: "png" | "webp" | "svg";
  objectUrl: string;
  width?: number;
  height?: number;
  anchor: { x: number; y: number };
  baseScale: number;
}

export type CreatorPlacementPresetId =
  | "ground"
  | "low"
  | "middle"
  | "upper"
  | "sky"
  | "free";

export type CreatorMotionPresetId =
  | "still"
  | "gentle-sway"
  | "float"
  | "pulse"
  | "twinkle";

export interface CreatorRoleDraft {
  role: PaletteRole;
  asset: CreatorAssetDraft | null;
  placementPreset: CreatorPlacementPresetId;
  motionPreset: CreatorMotionPresetId;
}

export interface CreatorPaletteDraft {
  version: "picture-score:creator-palette-draft:v1";
  id: string;
  name: string;
  authorName: string;
  roles: Record<PaletteRole, CreatorRoleDraft>;
}
```

`objectUrl` is runtime-only in v0.10-A. Do not persist it.

## Default empty draft

The five roles are always visible and ordered:

1. melody
2. harmony
3. rhythm
4. ornament
5. resonance

Defaults should already suggest a readable world:

| Role | Placement | Motion |
| --- | --- | --- |
| melody | middle | gentle-sway |
| harmony | upper | float |
| rhythm | ground | still |
| ornament | sky | twinkle |
| resonance | low | gentle-sway |

The creator can change presets, but cannot accidentally delete a semantic role from the editor.

## Presets

Creator-facing controls must not expose raw clustering/minDistance/amplitude/speed values in v0.10-A.

### Placement presets

Each preset compiles to an existing `PlacementRule`.

Suggested starting values:

```ts
const placementPresets = {
  ground:  { zone: "ground", clustering: 0.28, minDistance: 0.12, scaleRange: [0.75, 1.05], rotationRange: [-8, 8] },
  low:     { zone: "low",    clustering: 0.34, minDistance: 0.13, scaleRange: [0.80, 1.12], rotationRange: [-10, 10] },
  middle:  { zone: "middle", clustering: 0.42, minDistance: 0.14, scaleRange: [0.85, 1.15], rotationRange: [-12, 12] },
  upper:   { zone: "upper",  clustering: 0.36, minDistance: 0.14, scaleRange: [0.80, 1.10], rotationRange: [-15, 15] },
  sky:     { zone: "sky",    clustering: 0.25, minDistance: 0.15, scaleRange: [0.70, 1.00], rotationRange: [-18, 18] },
  free:    { zone: "any",    clustering: 0.30, minDistance: 0.14, scaleRange: [0.75, 1.10], rotationRange: [-20, 20] },
} satisfies Record<CreatorPlacementPresetId, PlacementRule>;
```

Exact values may be tuned by QA, but presets remain named semantic choices.

### Motion presets

Each preset compiles to existing `MotionProfile`.

Suggested mapping:

```text
still        -> idle none, birth fade
 gentle-sway -> idle sway, birth grow
float        -> idle float, birth rise
pulse        -> idle pulse, birth pop
 twinkle     -> idle twinkle, birth fade
```

All presets must define a Reduced Motion fallback through the existing palette schema.

## Compile contract

```ts
export interface CompileCreatorPaletteResult {
  ok: boolean;
  palette?: PaletteDefinition;
  errors: CreatorPaletteValidationError[];
}

export function compileCreatorPalette(
  draft: CreatorPaletteDraft,
): CompileCreatorPaletteResult;
```

Rules:
- compilation is pure
- no React dependency
- no file reads inside compiler
- every role requires one valid asset for a complete preview
- compiled palette id is derived from draft id, never file name
- asset id is deterministic from palette id + role
- `src` comes from the role asset object URL
- author defaults to local creator name when supplied
- limits use safe v0.10 defaults, not user-editable raw numbers
- environment uses a conservative neutral default for v0.10-A

## Validation

Validate before compilation:

### Palette
- non-empty name
- five role records present

### Asset
- exactly one asset per role in v0.10-A
- accepted MIME/file type: PNG, WebP, SVG
- reject unknown extension/MIME combinations
- reject zero-byte file
- explicit file-size cap
- safe dimensions once decoded

Suggested first cap:
- 2 MB per asset
- 10 MB total in-memory imported source files

These are MVP guardrails, not final product limits.

### SVG
For v0.10-A, treat SVG as an image resource rather than injecting SVG markup into the DOM. Use an object URL in `<image href>` through the existing renderer.

## Object URL lifecycle

The Lab owns imported object URLs.

Rules:
- revoke replaced asset URL
- revoke removed asset URL
- revoke all owned URLs on unmount
- compiled PaletteDefinition may reference current object URLs only while Lab is alive
- persistence work in #35 replaces this runtime-only representation

This prevents the prototype from leaking blobs during repeated imports.

## Preview behavior

Use the existing Core Meaning fixtures and `ScoreBloomSession`.

Preview state:
- fixture id
- target time
- playing / paused
- reduced motion
- preview palette: Clearing or compiled draft

When the draft changes:
1. validate
2. compile if valid
3. recreate only the draft preview session
4. preserve selected fixture and target time
5. seek the new session to current target time

Do not reset the entire page or mapper.

## Sample assets

A `Use sample assets` action may fill the five slots from Prism proof assets so the Lab is testable without local files.

Important:
- the sample action is demo/QA convenience
- the real path remains File input -> object URL -> draft -> PaletteDefinition

## Error UX

Errors belong to the role card that caused them.

Examples:
- `Add an image for Rhythm`
- `SVG, PNG, or WebP only`
- `This file is larger than 2 MB`
- `Could not read this image`

Avoid exposing schema terminology such as `AssetVariant` or `PlacementRule` to creators.

Global preview state:
- incomplete draft: keep last valid preview or show a calm empty stage
- never crash the preview because one file is bad

## Performance

No per-frame React state loop.

Reuse the existing semantic-revision update pattern. CSS/SVG owns idle motion.

Recompiling a draft should be limited to creator input changes, not playback frames.

## Tests

- complete five-role draft compiles
- deterministic ids
- preset mapping exact
- source object URLs preserved
- no Musical IR / WorldEvent dependency

### validation tests
- missing role asset
- unsupported format
- oversized file metadata
- bad name
- all five valid -> no errors

### lifecycle tests
Where practical, isolate object URL ownership behind helpers so replacement/revoke behavior is testable without coupling to React.

### browser gate

- 360x800

- 1440x900
- load sample Prism assets
- compile preview
- switch Clearing <-> custom
- A-E fixtures still preserve semantic role profiles
- deterministic replay
- Reduced Motion
- no horizontal overflow
- no failed art assets
- existing release regression chain remains green

Manual file-picker import should additionally be smoke-tested in a browser QA script using generated tiny PNG/WebP/SVG fixture files if the current Playwright harness permits file upload.

## Persistence boundary

Do not implement persistence in this branch.

When #34 compile/preview loop is green, #35 introduces:
- creator palette repository abstraction
- IndexedDB-backed asset storage
- versioned metadata
- product selector

This avoids making storage architecture a blocker for discovering whether the authoring UX is any good.
