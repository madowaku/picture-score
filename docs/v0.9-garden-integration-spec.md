# Picture Score v0.9 — Garden Integration Implementation Spec

Issue: #16
Depends on: #12, #13, #14, #15
Branch: `feat/v0.9-garden-integration`

## 1. Goal

Connect the new semantic runtime to the existing Garden without breaking ALIVE, CLEARING, WONDER, ENSEMBLE or WEAVE.

The v0.9 runtime path becomes:

```text
MusicalTimeline
  -> WorldEvent[]
  -> EventScheduler
  -> PaletteRuntime
  -> PaletteCue[]
  -> EntityStore / EnvironmentState / LineageStore
  -> ScoreBloomLayer + existing Garden layers
```

The existing Garden transport remains the audio/arrangement engine. SCORE BLOOM observes the same transport clock and renders a deterministic semantic world beside the existing persistent Growth/WEAVE systems.

For the existing drawing-derived Garden, `gardenScoreBloomSource()` is a read-only compatibility bridge from current `MusicIR` into one canonical 16-beat `MusicalTimeline`. Its identity excludes artwork/listener positions, so dragging never recreates the semantic session. Repeated Garden playback re-hears the same semantic events instead of inventing duplicate world entities on every loop.

## 2. Non-goals

- Do not replace `GardenTransport` scheduling or arrangement logic.
- Do not rewrite ALIVE, WONDER, ENSEMBLE or WEAVE.
- Do not migrate `picture-score:garden:v1`, Growth v1 or WEAVE v1 storage.
- Do not mutate source Stroke/Score/Music IR.
- Do not drive hundreds of entity animation values through React state every frame.
- Do not add Creator Palette UI in this issue.

## 3. Existing runtime facts to preserve

`GardenTransport` already owns one AudioContext, schedules in quarter-beat lookahead slices, updates moved works in place through `update(state)`, and exposes a read-only `beat` derived from the AudioContext clock. Dragging/moving works must continue to call `update()` rather than restarting transport.

Existing audible Growth is fed by `GardenTransport.onHeard`, and Growth v1 / WEAVE v1 persistence is independently flushed from `GardenView`. SCORE BLOOM must not replace or award those persistent systems.

Clearing geometry already protects source ink with `ClearingMask`, and legacy Growth assets now come from official `clearingPalette`. SCORE BLOOM rendering should reuse the same clearing exclusion principle.

## 6. EventScheduler

The scheduler owns an immutable, already-sorted `WorldEvent[]` and one integer cursor.

```ts
export class EventScheduler {
  constructor(events: readonly WorldEvent[]);

  get cursor(): number;
  reset(): void;
  flushUntil(time: number, emit: (event: WorldEvent) => void): number;
  replayTo(time: number, emit: (event: WorldEvent) => void): number;
}
```

Rules:

1. `flushUntil(t)` emits each event with `event.time <= t` exactly once.
2. Repeated `flushUntil(t)` at the same time emits nothing.
3. `reset()` sets cursor to zero only.
4. `replayTo(t)` resets, then emits all events through `t` in canonical order.
5. Reject non-finite or negative target times.
6. Scheduler does not know Palette, Garden, React or audio.
7. Duplicate protection remains upstream in normalized Musical IR / WorldEvent mapping, but scheduler tests also assert that a cursor cannot double-fire an event.

## 7. GardenTransport clock extension

Do not replace its scheduler. Add the smallest public clock/control surface needed by SCORE BLOOM.

```ts
get paused(): boolean;
get time(): number; // seconds from transport start, derived from beat and bpm

async pause(): Promise<void>;
async resume(): Promise<void>;
seek(timeSeconds: number): void;
```

### `time`

```ts
return this.state ? this.beat * 60 / this.state.bpm : 0;
```

### pause

- Valid only while `running`.
- Mark `paused = true` before awaiting suspension.
- Suspend this transport's AudioContext.
- Do not call `stop()`.
- Preserve lanes, plan, phase, startTime, Growth/WEAVE state and Garden placement.
- `schedule()` returns early while paused.

### resume

- Resume the same AudioContext.
- Clear `paused`.
- Do not recreate lanes or restart from beat zero.

### seek

v0.9 seek is deterministic phase repositioning, not audio-file scrubbing.

1. Clamp to `>= 0`.
2. Convert seconds to target beat using current Garden BPM.
3. Clear scheduled voices and transient life presentation from all lanes.
4. Re-anchor `startTime = ctx.currentTime - targetBeat * secondsPerBeat`.
5. Set `next` to the next quarter-beat boundary at/after the target.
6. Set `planBeat = -1` so arrangement is rebuilt.
7. Reset `heardTick = -1` so no missed/background Growth is awarded.
8. Clear transient spotlight/life state.
9. Preserve current Garden object positions and lane definitions.
10. Do not write Growth v1 or WEAVE v1 during the seek reconstruction.

The semantic session performs its own reset + replay after the transport seek.

## 8. EntityStore

EntityStore is mutable runtime state, not React state.

```ts
export class EntityStore {
  apply(cue: PaletteCue, time: number): boolean;
  reset(): void;
  snapshot(): readonly WorldEntity[];
  get(id: string): WorldEntity | undefined;
}
```

### spawn cue

Create one entity with `id = cue.id`.

Persist:

- palette asset
- position hint
- scale/rotation
- motion
- cue seed
- `sourceEventId`
- `worldEventId`
- `paletteCueId`

Ignore a duplicate spawn id instead of duplicating it.

### react cue

If `targetCueId` exists, update that entity. Otherwise apply to all existing entities of `targetRole`.

Update only semantic reaction state:

```ts
reaction.amount
reaction.direction
reaction.duration
reaction.revision++
```

Do not calculate per-frame sway/twinkle values here.

### bounds

PaletteRuntime already enforces role/total spawn budgets. EntityStore additionally refuses a store size above `palette.limits.total` as a defensive invariant.

## 10. ScoreBloomSession

```ts
export interface ScoreBloomSessionOptions {
  trackId: string;
  seed: string | number;
  timeline: MusicalTimeline;
  palette: PaletteDefinition;
  reducedMotion: boolean;
}

export class ScoreBloomSession {
  constructor(options: ScoreBloomSessionOptions);

  advanceTo(time: number): boolean;
  seek(time: number): boolean;
  reset(): void;
  snapshot(time?: number): WorldSnapshot;
  inspect(entityId: string): EntityOrigin | undefined;
  get revision(): number;
}
```

Construction:

1. Normalize timeline.
2. Map timeline to deterministic WorldEvents using the supplied track seed.
3. Create EventScheduler.
4. Create PaletteRuntime.
5. Create EntityStore and LineageStore.

### applying one WorldEvent

```text
WorldEvent
  -> paletteRuntime.apply(event)
  -> PaletteCue[]
  -> EntityStore / environment
  -> lineage
  -> revision++ if visible state changed
```

`advanceTo(time)` calls scheduler `flushUntil(time)`.

`seek(time)` does:

```text
paletteRuntime.reset()
entityStore.reset()
lineage.reset()
scheduler.replayTo(time, applyEvent)
```

For the same timeline + seed + palette + target time, `snapshot()` must deep-equal across runs.

## 11. Environment ownership

PaletteRuntime remains the source of environment state. ScoreBloomSession reads `paletteRuntime.snapshot().environment` when producing a WorldSnapshot.

Do not mirror environment into React state every frame.

## 12. Garden integration

### Garden semantic adapter

`gardenScoreBloomSource(garden)` reads the existing drawing-derived `MusicIR` and emits one canonical 16-beat `MusicalTimeline`:

- melody object -> melody events
- harmony object -> harmony events
- rhythm object -> rhythm events
- decoration object -> ornament events
- drone object -> resonance events
- one section event at time zero

Its deterministic identity includes BPM + stable object/music signatures and deliberately excludes `world` positions and listener position. Source Stroke/Score/Music IR remains untouched.

### GardenView owns semantic integration through a bridge

`GardenView` renders one `GardenScoreBloomBridge` between legacy Growth and GardenLife. The bridge owns the session ref and published frame so the already-large Garden component does not inherit semantic runtime state machinery.

The session is recreated only when its semantic identity changes:

- musical source / Garden object set
- BPM
- palette id/version
- track seed
- reduced-motion preference

It is **not** recreated when:

- a Garden work is dragged
- selection changes
- listener moves
- relation UI changes
- ALIVE/WONDER presentation changes

### update loop

Use one `requestAnimationFrame` only while Garden playback is running.

```ts
const tick = () => {
  const session = scoreBloom.current;
  if (!session) return;

  const changed = session.advanceTo(transport.time);
  if (changed) {
    setScoreBloomFrame({
      revision: session.revision,
      snapshot: session.snapshot(),
    });
  }

  raf = requestAnimationFrame(tick);
};
```

The bridge additionally treats a backward transport clock as a seek seam and uses deterministic `session.seek(time)` reconstruction.

This is event-driven React state. At 60fps with no semantic event, React receives zero updates.

## 13. ScoreBloomLayer

Add a new non-interactive SVG layer rather than overloading Growth v1.

Layer order:

```text
WEAVE relationship ground
legacy Growth habitats
SCORE BLOOM semantic entities
GardenLife / Ensemble cues
source artwork
listener / controls
```

The exact z-index may be adjusted after visual QA, but source artwork must remain above generated pigment.

Props:

```ts
interface ScoreBloomLayerProps {
  snapshot: WorldSnapshot;
  palette: PaletteDefinition;
  clearings: Clearing[];
  layout: GardenLayout;
  debugEntityId?: string;
}
```

Use `ClearingMask` so generated pigment never paints over source artwork.

## 14. Deterministic placement

`PaletteCue.positionHint` is semantic, not final screen geometry.

Add `scoreBloomPlacement.ts`:

```ts
resolvePalettePosition(
  entity: WorldEntity,
  palette: PaletteDefinition,
  clearings: readonly Clearing[],
): { x: number; y: number }
```

Convert normalized hints into the 1000x1000 Garden coordinate system.

Zone constraints:

```text
ground  y 700..940
low     y 560..820
middle  y 320..720
upper   y 140..480
sky     y 60..300
any     y 60..940
```

Use the entity seed for any deterministic nudge. If the candidate overlaps a clearing:

1. try deterministic radial offsets in a fixed order,
2. keep inside Garden bounds,
3. stop at the first non-intersecting candidate,
4. if none fit, suppress rendering of that entity rather than covering the drawing.

No `Math.random()`.

## 15. Motion

CSS/SVG handles idle motion from `ResolvedMotionProfile`.

Use classes/data attributes such as:

```text
data-score-bloom-role
data-score-bloom-motion
data-score-bloom-birth
data-score-bloom-reaction-revision
```

Allowed idle presets remain those from Palette v1: none, sway, float, pulse, twinkle.

Reduced Motion uses the already-resolved PaletteRuntime fallback. No second accessibility policy is invented in the renderer.

## 16. Playback behavior

### start

1. Start existing GardenTransport.
2. Reset semantic session to t=0.
3. Start semantic RAF observer.

### pause

1. `await GardenTransport.pause()`.
2. Stop semantic RAF observer.
3. Keep current snapshot displayed.

### resume

1. `await GardenTransport.resume()`.
2. Resume semantic RAF observer from the unchanged transport time.

### restart

1. transport seek to 0.
2. semantic session seek to 0.
3. restart playback without recreating Garden works.

### seek

1. Remember whether transport was playing.
2. Pause semantic RAF.
3. `GardenTransport.seek(targetTime)`.
4. `ScoreBloomSession.seek(targetTime)`.
5. Publish exactly one new ScoreBloomFrame.
6. Resume RAF if transport was playing.

No WorldEvent may fire twice because scheduler cursor is reconstructed from zero.

## 17. Snapshot persistence

Do not modify existing Garden/Growth/WEAVE keys.

Introduce only if the product UI actually exposes saved SCORE BLOOM works in #16:

```text
picture-score:world:v1
```

If no save UI is exposed yet, keep snapshots in memory and test serialization only. Do not create silent localStorage growth.

Serialization contract:

- JSON-safe
- no DOM nodes
- no AudioNodes
- no functions
- deterministic ordering by entity creation time then id

## 19. Validation matrix

### scheduler/runtime

- same-time event ordering
- no duplicate fire
- repeated `advanceTo(t)` no-op
- seek backward + forward yields the same snapshot
- entity limits enforced
- lineage survives snapshot/replay

### Garden compatibility

- moving a work does not restart transport or semantic session
- listener movement does not change semantic identity
- object add/remove/BPM changes rebuild semantic identity deterministically
- ALIVE note/relation cues still fire
- Growth v1 still records only actual audible quarter-beats
- WEAVE evidence still comes from actual Life events
- source artwork remains above generated pigment

### accessibility

- reduced motion reconstructs the same entity identities
- only motion profile changes
